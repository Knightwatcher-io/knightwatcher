The services it reads, and what it runs on.

Services

Built-in providers for the services most homelabs run, and a way to read anything else that answers with JSON. A small collector does the reading and writes one file; the display only reads that file. Your keys stay in a .env file on your machine, and each goes only to its own service. The collector only reads, but several services offer no read-only key, so .env may hold a login that could change them. Treat it as you treat those services' own configuration.

What the collector reads itself

  • Bans

    • fail2ban, from its own database

  • This machine

    • CPU
    • Memory
    • Disks
    • Backup log
    • Updates running
    • SSH sessions

  • The network

    • Internet
    • DNS
    • Up to 32 devices
    • Docker containers, through a read-only Docker API proxy that you run (the compose file has none, and the collector gets no Docker socket)

  • Anything else

    A generic check reads one value from any address that answers with JSON, tests it, and shows your own words when the test holds. For a whole service, write a provider file: it's data, read by the same rules as the built-in ones, and never runs as code.

Requirements

What you need, all of it tested:

  • Linux with Docker and its compose plugin, and the acl package. The image is published for x86-64 and 64-bit ARM, and tested on both: an x86-64 server and a Raspberry Pi 5 on a 64-bit OS.
  • Two containers from one image. They use about 35 MB of memory between them and almost no CPU while idle.
  • A modern browser on the display, a tablet's for example.

Supported systems:

  • The host: Linux with Docker and its compose plugin. Tested on Ubuntu and on Debian 13 (on the Raspberry Pi); other distributions should work. A 32-bit ARM system cannot run the image.
  • Windows and macOS hosts are not supported.
  • The display: any modern browser.
