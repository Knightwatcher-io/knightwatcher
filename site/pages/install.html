Install

On a Linux machine with Docker, its compose plugin and the acl package.

Quick start

knightwatcher-io/knightwatcher

Three steps, one of them a permissions step, then you add the services you run.

What you need: the requirements.

  1. Get the files and make the folders

    git clone https://github.com/knightwatcher-io/knightwatcher
cd knightwatcher
cp config.example.toml config.toml
cp .env.example .env && chmod 600 .env
mkdir -p var/out var/server
setfacl -m u:10001:rwx var var/out var/server
setfacl -d -m u:10001:rwx,u:$(id -u):rwx var var/out var/server
touch var/backup.log

    The containers run as uid 10001; the two setfacl lines let them write to those folders.

  2. Point it at two things, now or later

    .env as copied starts as it is: KW_BACKUP_LOG is the empty ./var/backup.log, which raises nothing until it records a backup, and KW_DATA_DISK is ./var. Set them to your real backup log and to any folder on the disk to watch. Both must exist.

  3. Start it

    docker compose up -d

    Compose pulls ghcr.io/knightwatcher-io/knightwatcher, or builds it from the checkout with docker compose build, and runs the collector and the display's server from it. KW_VERSION in .env pins a release. Open http://<this machine>:8080/, or the port KW_SERVER_PORT sets: the knight appears at once, and the first readings within a minute.

The example config turns on the sources that read this machine, plus an internet check and a DNS check. Each service is written out in config.toml but commented: remove the #, add your address, and put its key in .env.

The display has no login, and a streams service shows who is watching what (show = "count" hides the names). Docker publishes it on every address of the host. Set KW_SERVER_ADDRESS=127.0.0.1 to keep it to the machine, behind a reverse proxy with a login. The admin password covers the admin page only. Never put the display on the internet without a login.

Usage counts are off unless you turn them on. If you are happy to help, set KW_ANALYTICS=on in .env: what leaves your network.

What leaves your network

Two things at most, and nothing else.

The usage counts

If you turn them on, the collector sends one small report at start and every six hours: a random install id, the version, the install's age and uptime, the world and look you chose, which built-in sources are on, how many imports and checks you have, and how many displays opened the page in the last six hours. The receiver adds the day and the country Cloudflare sees. No name, address, title or credential is in it. The receiver runs on Cloudflare, keeps no IP address, and its code is in the repository's telemetry/ folder. They stay off unless .env says KW_ANALYTICS=on; with off, or the line left out, nothing is sent.

Two checks

The example config asks https://1.1.1.1/cdn-cgi/trace (Cloudflare's) whether the internet is up, and asks your DNS server (the example uses the host's own resolver) to look up example.com. Both addresses are in config.toml, and either check can be removed there.

Past that, the collector contacts only the addresses you give it, and the display and the server contact nothing outside your network.
